## 🔬 Compétences techniques clés

### Architecture Logicielle (Niveau Industriel)
- **Domain-Driven Design (DDD)** : Aggregates, Bounded Contexts (13+ retail, 11 accounting/finance, 8 control plane), Value Objects, Rich Models, Domain Events, Ports & Adapters (Protocol classes)
- **CQRS** : Séparation stricte Command Side (agrégats/écritures) / Query Side (read-model projections via SQLAlchemy)
- **Event Sourcing** : `CanonicalEventEnvelope` avec versionnage SemVer, validation JSON Schema (draft 2020-12), ordre temporel (`occurredAt ≤ observedAt ≤ recordedAt`), classifications de sécurité
- **Transactional Outbox / Inbox** : Écriture atomique métier + événements, dédoublonnage idempotent, zéro perte réseau
- **Clean Architecture** : Dépendance inversée, séparation Domaine (Python pur) / Infrastructure / Application, composition root FastAPI
- **Modélisation** : Diagrammes Mermaid (architecture, machine à états, séquences, classe UML), documentation source-of-truth gouvernée

### Design System & UX Professionnelle
- **MDI Workbench** (VS Code-inspired) : 7 Parts contractuelles — Titlebar, Activitybar, Sidebar/Explorer, EditorTabs (MDI), Auxiliary Inspector, Panel `Ctrl+J`, Statusbar
- **Design System Flat Pro** : Haute densité, hairlines 1px (`#2A2A2A`), fonds étagés, typographie `Inter` + `JetBrains Mono` pour données financières, grille 4px/8px, WCAG AA
- **Command Palette universelle** (`Ctrl+K`) : Recherche floue produits/clients/actions
- **No Modal by Default** : Règle des 6 niveaux (Inline → Auxiliary → Editor → Panel → Overlay → Dialog)
- **Barcode Scanner Interceptor** : Détection HID par vélocité de frappe (>8 car. / <20ms) sans perturber le champ actif
- **Responsive** : Grille adaptative Desktop ≥1200px / Compact / Tablette / Mobile
- **Persistance des onglets** : Dirty state `●`, restauration crash, séparation Workspace UI vs Drafts métier (AD-25/27)
- **Intent-Only Navigation** : Zéro `Navigator.push()` ; tout passe par `NavigationIntent` → `ContextOrchestrator` → TabManager

### Server-Driven & Agent-Driven UI
- **SDUI (Server-Driven UI)** : Intermediate Representation (ScalarioSurfaceDefinition) protocol-agnostic, cache rendu vs données, versioning de schéma, capabilities negotiation
- **Component Catalog** : Catalogue fini de composants locaux de confiance (DataGrid, MoneyInput, QuantityInput…) — jamais de code serveur exécutable
- **Policy Guard local** : Double validation RBAC/ABAC locale même pour les surfaces pilotées par le serveur
- **GenUI / A2UI Adapter** : Surfaces générées par l'agent rendues dans le `UiProtocolAdapter`, A2UI v0.9 découplé du métier
- **Agentic Workbench** : Agent en tant que Context Producer (ouvre des onglets comme l'Explorer)
- **Niveaux d'autonomie** : L0 Explain → L1 Navigate → L2 Propose → L3 Execute with Approval → L4 Autonomous (RBAC-aware)
- **Proposal Before Mutation** : `Intent → Proposal → Preview → Approval → Command → Commit` (AD-17)

### Orchestration d'Agents Autonomes (BMAD)
- **Pipeline multi-rôles** : Spec Writer → Adversarial Reviewer (Red Teaming) → Cross-Domain Validator → Human Checkpoint
- **Revue contradictoire automatisée** : Grille de risques (Domain Ownership Leak, Statutory GL Mutation, Destructive Mutation, Temporal Ambiguity, Offline/Idempotency Failure, Security Boundary)
- **Rapport `ArchitectureReview` structuré YAML** avec findings critical/major/minor et boucles auto-correctives (max 3)
- **Gouvernance humaine** : Approbation formelle des invariants AD-xx, arbitrage des blocages
- **Invariants scellés** : Contrats imposés aux agents (zéro float financier, zéro Navigator.push, frontières domaine/infra)

### Sécurité & Audit
- **RBAC + ABAC (Google CEL)** : Rôles + politiques d'attributs dynamiques évaluées par moteur Common Expression Language
- **Step-Up Authorization** : Override par PIN superviseur (PBKDF2/HMAC), verrouillage après 3 échecs, jeton non-rejouable à durée limitée (5 min)
- **Dual Custody / Séparation des tâches** : Approbation multi-acteurs, `verifiedBy != assignedTo` pour les réparations critiques
- **Audit Trail immuable** : Chaîne de hachage SHA-256 append-only, détection de falsification
- **Crypto-Shredding GDPR** : Anonymisation par destruction de clé sans briser l'intégrité de la chaîne
- **Break-glass** : Accès d'urgence avec attestation
- **Row-Level Security (PostgreSQL)** : Isolation multi-tenant au niveau BD, `SET LOCAL app.current_tenant`

### Offline-First & Résilience (Distributed Systems)
- **Local Outbox** : SQLite chiffré, file d'attente locale, sync delta batch dès reconnexion
- **Baux Cryptographiques (Authority Leases)** : Jeton JWS signé, expiration, liste de révocation, autorisation hors-ligne
- **Zero-LWW** : Jamais de résolution par timestamp seul ; Three-Way Merge, Commutative Delta, conflits escaladés à adjudication humaine
- **Chaos Engineering** : 15 types de fautes injectables (network blackout, disk full, OOM, clock drift), steady-state hypothesis, pré/post-flight checks
- **Projection Engine** : Checkpoints monotones, tokens d'invalidation temps réel (entité/collection/global)
- **Optimistic Concurrency Control (OCC)** : Détection de conflit par version, idempotency keys

### Fiabilité Financière & Métier
- **DecimalPolicy (9 types sémantiques)** : Money 19,4 / AccountingMoney 24,6 / UnitPrice / Quantity / ExchangeRate / Percentage / TaxRate… avec garde-fou par analyse statique AST (zero float dans les modèles financiers)
- **UUIDv7** : RFC 9562 time-ordered, généré côté client pour indexation optimale
- **Comptabilité double-entrée** : Débit = Crédit, period close, consolidations intercompany sans réécriture des livres statutaires
- **Moteur de pricing 5-cascade** : Base → Accords B2B → Volumes → Promotions (AST) → Coupons, avec floor price
- **Fidélité ledger-derived** : Points FIFO avec détection de double-dépense offline, conformité IFRS 15
- **Invariants par domaine** : Cash ledger-derived, expenses ners déplacent pas l'argent, count ne réécrit pas la vérité attendue (AD-30 à AD-76)

### Backend
- **FastAPI** asynchrone, Pydantic v2, Uvicorn, CORS regex, OpenTelemetry-compatible tracing (corrélation IDs, response time headers)
- **PostgreSQL 16** + RLS multi-tenant, indexation B-Tree & GIN (codes-barres, téléphones, dates)
- **SQLAlchemy 2.0** pour projections read-model
- **WebSocket** temps réel multi-caisses, **Celery** workers (PDF, WhatsApp, rapports)
- **Mapping d'exceptions DDD** vers RFC-compliant HTTP status codes (404/409/422/403/400)

### Frontend
- **Flutter Desktop** (Linux/Windows) + Mobile responsive, window_manager
- **Riverpod** (ProviderContainer, StateNotifier), feature-based modular architecture
- **WorkbenchShell** : MDI tabs persistants, dirty state, restauration après crash
- **PDF** génération (reçus/factures) + **impression thermique ESC/POS**
- **QR code** (scan+génération), **fl_chart** dashboards, **flutter_secure_storage** (JWT), **multicast_dns** (découverte réseau)

### DevOps & Distribution (Windows)
- **GitHub Actions** complet : lint (Ruff) → tests (pytest) → build Flutter → PyInstaller → Inno Setup installer → GitHub Release avec checksums SHA256
